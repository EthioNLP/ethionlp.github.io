Forms and pull requests

Which applies depends on what you are adding, not on how technical you are.

Through a form

You fill in a few fields. A workflow turns your answers into a proposed change to the site, and a maintainer merges it.

Many of them are GitHub issue forms, which need a free account.

Through a pull request

If Git is something you already use, edit the files directly. It is faster for changes the forms do not cover, and it is required for changes to the code itself.

The contributor guide has the local setup: two commands, and the site runs on your machine with live reload.

In both cases a maintainer reviews the change before it is published.

What happens after you submit

The same four steps for every form.

  1. Your answers become a proposed change

    A workflow reads the form and writes the file it describes, then opens it as a pull request against this site. This is automatic and usually takes under a minute.

  2. A maintainer reads it

    Usually within a few days. Questions come back in the same thread.

  3. It is merged and the site rebuilds

    Publishing is automatic on merge, so the change is live a few minutes after a maintainer merges it.

  4. From then on it is updated automatically

    If you gave a Hugging Face, GitHub, Scholar or ORCID identifier, a nightly sync picks up the work you publish afterwards.

Common obstacles

Without a GitHub account

Sharing news works over a plain web form, email or Telegram, none of which need one. For anything else, write to {{ site.email }} and a maintainer will file it for you.

Unsure whether it is worth adding

{{ uncovered }} of the {{ cat.totals.languages }} catalogue entries have no model or dataset, so a few thousand sentences in one of them add a resource that does not yet exist. Negative results and approaches that did not work are also in scope. Submit it and a maintainer decides.

Early in your career

Many of the ways listed here do not depend on seniority. Fixing a wrong affiliation, adding a paper the sync missed, or writing a caption for a photograph all improve the site, and mentoring is open to those a step ahead of the person asking.

{%- comment -%} ── House rules ──────────────────────────────────────────────── {%- endcomment -%}

What we ask

Only add people who have agreed to it. Being in an organisation is not consent to appearing on a public website. Anyone imported automatically is held unpublished until they confirm, and the same standard applies to anything you submit: name a person only if they are happy to be named. That covers photograph captions too.

Link to the thing, do not attach it. Publish a dataset or a model where it belongs, on Hugging Face, Zenodo or a repository, and give us the identifier. It then stays findable if this site is withdrawn, and the nightly sync keeps its record current without manual editing.

Say where a figure came from. Every number on this site is meant to be traceable to a source. If you add one, add where it is from, and prefer an upstream fix, in Glottolog or Wikidata, over a correction that only helps this page.

Write plainly. Describe what a thing is and what it contains, rather than why it matters. Everything on this site is licensed CC BY 4.0, so what you add is reusable by anyone.

Getting help

Ask on the mailing list or open an issue. A half-formed question is fine.
